# Publish the existing workshop on Render

This is a Render deployment, not a ChatGPT Site. The original course, interactive Plan-mode interview exercise, approval steps, computer-use prompt, slide uploads, gallery and PowerPoint combination are preserved without rewriting their source files.

## Status

The deployment configuration is prepared. It does not create a hosting service merely by being committed. The original website archive must also be present in GitHub, and the Render account holder must approve the billable deployment. Local test results are in `LOCAL_TEST_RESULTS.json`; these are not evidence of a live Render deployment.

## 1. Add the original archive

Upload the original **AI_for_science_workshop_v4.zip**, without extracting or renaming it, to the repository root alongside `render.yaml`.

GitHub upload page: https://github.com/afvallejo/ai-for-science-workshop/upload/main

Expected size: 10,765,964 bytes. SHA-256:

```text
4b3d767f823721d7693518b0fe23c216f52dde62580ea67d00f9f28e460d5e86
```

The build deliberately stops when the ZIP is absent or its checksum differs. It extracts only the runtime into `website/`. Only `website/public/` is publicly served. Recovery archives, test reports, test fixtures and the server source are not served by the application. Existing repository teaching materials remain untouched.

## 2. Review and approve the deployment

Open: https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Fafvallejo%2Fai-for-science-workshop

Choose the intended Render workspace and review the account and charges before approval.

The Blueprint requests one Starter Python web service in Frankfurt and a 1 GB persistent disk. Published compute and disk rates checked on 17 September 2026 give a base of **US$7.25/month**, before taxes, any workspace fees, and usage overages. Check the actual quote in Render before proceeding.

No separate disk-creation step is needed when applying this Blueprint. Do not create a static-only site. Automatic redeploys are disabled so repository changes do not interrupt an active workshop; trigger later deployments deliberately from Render.

## 3. Open the test room after the deployment is live

Use the actual HTTPS address assigned by Render. The main course is at `/`; the participant exercise is at:

```text
/room/?room=SCITEST2
```

The startup script creates **SCITEST2** on the first successful start using the mounted disk. This predictable code is deliberately for non-sensitive testing, not private material. It is not a live room until the deployment succeeds. Closed submissions and uploaded slides are not reset on restart. Deleting the test room does not cause it to reappear on restart.

For facilitator access, open **Facilitator**, expand **Reconnect to a room you created**, and enter `SCITEST2` plus the value of `WORKSHOP_TEST_ROOM_KEY` from the Render service's Environment settings. Keep that key private. Save the room management key using the site's button.

To create a new workshop room with a random code, use `WORKSHOP_HOST_KEY` in the site's room-creation form. Both keys are generated by Render; neither is stored in this repository. Do not replace their values without a recovery plan for existing rooms.

Share only the participant URL or room code, never either management key.

## Before participants use it

Test from two actual devices: upload one non-sensitive slide from each device, confirm both server receipts and gallery entries, combine them, and inspect the downloaded PowerPoint in PowerPoint. Check one service restart retains the submissions. Local checks have passed, but public HTTPS, the real Render disk mount and browser access still require live verification.

The current exercise uses shared room codes, not individual participant authentication. It is for non-sensitive workshop contributions only. Export and retain the combined deck outside the service. Persistent storage is not a substitute for a backup. The existing merger is not a malware scanner. Maximum-size submissions and large-room memory usage have not been load-tested on the 512 MB Starter instance.

Private room data live under `/var/data/ai-science-workshop`. Startup refuses to run when the configured persistent disk is not mounted. The service runs a single application process. Do not move its database into `public/`, commit participant uploads, or add secrets to GitHub. Review Render backups and retention when deleting workshop data.
